3.1 chmod
Реализован перевод из буквенного и символьного в числовой (1 опция), считывание текущего файла (2 опция). Модификация прав (3 опция) работает только после применения 1 или 2.  
25 тестов
1) проверяет парсинг стандартного буквенного формата rwxr-xr-x, убеждается что все биты установлены правильно
2) проверяет парсинг с ведущим дефисом -rwxr-xr-x (обычный файл)
3) проверяет парсинг с буквой 'd' drwxr-xr-x (директория)
4) проверяет парсинг восьмеричного числа 755
5) проверяет парсинг восьмеричного числа 644
6) проверяет парсинг с ведущим нулем 0755
7) проверяет обработку неверного восьмеричного числа (999)
8) проверяет автоматическое определение восьмеричного формата
9) проверяет автоматическое определение буквенного формата
10) проверяет форматирование прав 0755 в буквенный вид -rwxr-xr-x
11) проверяет форматирование прав 0644 в буквенный вид -rw-r--r--
12) проверяет что для директории первый символ 'd'
13) проверяет получение прав у существующего файла
14) проверяет обработку несуществующего файла (возврат -1)
15) добавляет право на выполнение для владельца (u+x)
16) добавляет право на запись для группы (g+w)
17) убирает право на запись для группы и других (go-w)
18) устанавливает права на чтение и запись для всех (a=rw)
19) проверяет команду без указания категории (+x - применяется ко всем)
20) создает файл, устанавливает права 755 и проверяет результат
21) создает директорию, устанавливает права и проверяет что это директория
22) модифицирует права в программе и применяет их к реальному файлу
23) проверяет установку бита setuid (4755) и отображение 's' в позиции владельца
24) проверяет установку sticky-бита (1777) и отображение 't' в позиции других
25) проверяет установку бита setgid (2755) и отображение 's' в позиции группы

4.3 Бинарное дерево
Реализована балансировка дерева на этапе добавления иди удаления элементов. Для каждого узла идет подсчет высот левого и правого ветвей. Если идет смещение в лево или право хотя бы на 1, реализуется один из нескольких сценариев. Так получаем не более двух потомков для каждого узла дерева.
Также можно посмотреть как выглядит дерево. Для этого нужно в запущенном app сгенерировать n количество контактов при помощи 5 опции из селектора. С помощью 6 опции получить дерево. Автоматом заполняет значение empty в случае наличия одного потомка у узла и возмоности появления второго, при обновлении данных.
10 тестов:
1) Проверка инициализации. Корень равен NULL, высота, счетчик равны 0.
2) Добавление одного контакта. Проверка счетчика контактов, присвоение высоты, значения pb.root, соответствия строчного значения относительно внесенного.
3) Добавление 3 контактов А, B, C. Реализация балансировки дерева - получаем B как корень. Проверка высоты (2). 
4) Поиск нужного узла по имени/фамилии. Проверка соответствия found введенному значению.
5) Поиск контакта по имени должен возвращать 0 при отсутствия совпадений по имени/фамилии.
6) Удаление листа. Добавление 3 контактов А, B, C. Удаляем A. Проверка сохранения высоты, левой (удаленной) ветви. 
7) Удаление узла с одним потомком. Добавление двух контактов A, B. Удаляем B. Проверка соотвествия левого, правого ветвей NULL, поиск A, высота равна 1.
8) Удаление узла с двумя потомками. Добавление 3 контактов A, B, C. Удаляем B. Проверка соответсвия корня значению C, левой ветви A.
9) Обновление контакта. У контакта обновляется компания и должность. Далее обращаемся по поиску к contact.workplace и contact.jobtitle.
10) Обход дерева. Добавление 3 контактов А, B, C. Обход при помощи traverseTree левого поддерева, возвращение к корню, обход правого с сохранением контакта. Проверка результатов.
